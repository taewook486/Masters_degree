## 1. RQ3의 "해석 가능성" 주장 — 측정 불가능한 기여를 기여라고 부른다

v0.4에서 귀무가설을 `= Random Search`에서 `= Optuna(TPE)`로 격상한 건 올바른 방향이다. 그러나 핵심 차별점으로 내세우는 것이 *"자연어 기반 탐색 근거 설명 가능성"*이다.

이것이 논문 기여가 되려면 **해석 가능성을 측정하는 방법론**이 있어야 한다. 현재 설계서에는 없다. "rationale.md에 근거를 기록한다"는 단순 로깅이다. 이를 평가하는 지표가 없으면, 이건 과학적 기여가 아니라 소프트웨어 기능이다.

더 심각한 문제: Autoresearch 에이전트가 Claude API를 쓴다. 이 프로젝트 자체를 Claude Code로 개발했다. 에이전트에게 주는 프롬프트와 실험 결과 형식이 이 환경에 최적화되어 있을 가능성을 어떻게 배제하는가? 이건 통제 불가능한 편향이다.

**🔥 예상 질문**: *"'해석 가능성'이 높다는 것을 어떻게 측정했습니까? 정량 지표가 없다면 이건 기여 항목이 될 수 없습니다."*

## 2. Phase 1 결과의 STD=0.0 — 이미 발생한 데이터 무결성 문제

`results/phase1_baseline_pre_bertscore/phase1_summary.csv` 직접 확인 결과:

| 모델 | 데이터셋 | closed_acc_std | open_acc_std |
|------|----------|:--------------:|:------------:|
| qwen25-vl-3b | pathvqa | 0.0 | 0.0 |
| qwen25-vl-3b | slake | 0.0 | 0.0 |
| ... | ... | 0.0 | 0.0 |

9개 조건 전체 STD=0.0이다. 가능한 해석:

- **(a) 집계 버그**: 3개 시드 중 1개 결과만 집계됨 → `num_seeds=3`으로 표기됐으나 실질적 n=1
- **(b) 완전 결정론적 모델**: 3개 시드가 진짜 동일 출력 → seed 고정이 실제로 작동하지 않거나, 모델이 입력에만 의존

REQ-005를 "실험 재실행이 필요해서 스킵"으로 처리했는데, **이건 데이터 품질 위기다.** Phase 2 paired t-test의 기반이 되는 베이스라인 수치가 단일 시드에서 나온 것일 수 있다. Phase 2 진입 전 반드시 해결해야 한다.

## 3. ANOVA의 통계적 검정력 — Phase 1 통계 설계 자체가 잘못됐다

4개 모델, 각 3개 시드. 모델당 n=3이다.

Cohen's f=0.25(중간 효과 크기)를 감지하기 위한 one-way ANOVA(k=4, n=3/그룹)의 통계적 검정력은 **약 0.10~0.15**다. 유의수준 0.05에서 검정력 0.8을 달성하려면 그룹당 최소 n=45가 필요하다.

결과가 "p>0.05 → 모델 간 유의한 차이 없음"으로 나오면, 이것이 실제로 차이가 없는 건지 샘플이 너무 작은 건지 구분 불가능하다. **RQ1 자체를 검정할 수 없는 통계 설계다.** 3개 시드는 표준편차 계산용이 아니라 처리 단위여야 했다.

## 4. Max_steps 고정의 순환 논리

v0.4에서 "15분 고정 예산"을 "max_steps=200 고정"으로 변경했다. 논리는 "Ablation A(학습 곡선)로 200 steps와 최종 수렴 성능 간 순위 상관관계를 자체 실증한다"는 것이다.

이것이 순환 논리다. **Ablation A 자체도 max_steps를 어딘가에서 끊는다.** 그 끊는 지점의 타당성은 무엇으로 검증하는가? 인용한 Hyperband(Li et al., 2018)는 successive halving 알고리즘이지, "200 steps면 충분하다"는 근거가 아니다.

구체적 위험:
- `lora_rank=64, lr=1e-5`: 200 steps에서 warm-up도 안 됐을 수 있다
- `lora_rank=4, lr=5e-4`: 이미 과적합 구간일 수 있다

탐색 공간 전체에 걸쳐 200 steps가 "공정한 평가 시점"임을 별도로 보여야 한다.

**🔥 예상 질문**: *"200 steps라는 수치의 근거가 무엇입니까? 학습 곡선 초반 순위와 수렴 후 순위 간 Spearman 상관계수를 측정해서 보여주세요."*

## 5. WCA 가중치 — 임의 척도를 평가 지표로 제시한다

Weighted Clinical Accuracy의 가중치 (Diagnosis: 1.0, Location: 0.8, ...):

설계서 본문에 **"본 연구자가 부여한 임시 척도"** 라고 직접 명시되어 있다. 연구자 개인이 임의로 정한 가중치로 계산한 지표를 논문의 평가 지표로 제시하면 안 된다. 임상의 설문 연구, Delphi 법, 또는 선행 임상 문헌에서 근거를 가져와야 한다. 없으면 보조 지표로도 사용하기 어렵다.

동일한 논리로: ECE 임계값 0.05는 Guo et al.(2017)의 general image classification에서 나온 수치다. 의료 VQA에서의 적합한 ECE 임계값이 0.05라는 근거가 없다.

## 6. Gemma4-E2B의 공정성 문제

Gemma4-E2B는 "2.3B active / 5.1B total" Mixture-of-Experts 구조다. 추론 시 2.3B만 활성화되지만 저장된 지식은 5.1B 상당이다.

Qwen3-VL-2B, SmolVLM-2.2B(밀집 아키텍처)와 Gemma4-E2B(희소 아키텍처)를 "경량 VLM 비교"로 묶으면 이것은 사과와 오렌지 비교다. **파라미터 규모로 모델을 선정했다면, 활성 파라미터 기준인가 총 파라미터 기준인가?** 이 기준이 불명확하면 모델 선정 자체의 공정성이 흔들린다.

## 7. BERTScore 임계값 0.7 — 의료 도메인에서 검증되지 않은 수치

"BERTScore F1 >= 0.7이면 정답"으로 판정한다. 이 임계값의 출처가 없다.

더 중요한 문제: BioBERT 변형을 병행 보고한다고 했는데, **두 지표 간 판정 불일치 사례가 나왔을 때 어떤 것을 기준으로 삼는가?** 이 충돌 해결 방법이 사전에 정의되어 있지 않으면, 사후에 더 좋은 숫자를 선택하는 cherry-picking이 된다.

## 8. 다중 비교 문제 — 설계서 어디에도 언급이 없다

| 단계 | 검정 횟수 |
|------|-----------|
| Phase 1: ANOVA 후 Tukey HSD | 4모델 × 3데이터셋 쌍별 비교 |
| Phase 2: paired t-test + Wilcoxon + Bootstrap + Mixed-Effects | 동일 가설에 4가지 검정 병행 |
| Phase 3: KW + Mann-Whitney | 4전략 쌍별 비교 = 6회 |

총 비교 횟수가 20~30회 이상이다. 유의수준 0.05에서 전부 독립적으로 수행하면 **family-wise error rate ≈ 1-(0.95)^20 ≈ 64%**다.

Bonferroni 보정, Benjamini-Hochberg FDR 보정, 또는 최소한 이 문제에 대한 언급이 설계서 어디에도 없다.

## 9. Cross-dataset CF는 CF 측정이 아니다

"PathVQA로 훈련 → SLAKE로 평가"를 Catastrophic Forgetting 측정이라고 부른다. 그러나 PathVQA는 병리학(현미경 조직), SLAKE는 방사선/CT다. 이미지 도메인 자체가 다르다.

도메인이 다른 데이터셋에서의 성능 저하는 CF가 아니라 **도메인 특화의 예측 가능한 결과**다. CF는 "파인튜닝 전에 할 수 있었던 것을 파인튜닝 후에 못 하게 됐다"는 것이다. "한 번도 잘 못 하던 걸 여전히 못 한다"는 건 CF가 아니다. 측정하려는 현상의 정의 자체가 잘못됐다.

## 10. 하드웨어 16GB 검증 공백

Phase 1은 로컬 RTX 5060 Ti + RunPod RTX 4090 혼용이다. `phase1_summary.csv` VRAM 수치가 7.5~8GB로 일관된 건 어느 GPU에서 나온 수치인가?

더 중요한 것: **"소비자 GPU(16GB) 환경 실증"을 논문 제목과 목적에 명시했는데, Phase 2 훈련을 RTX 4090(24GB)으로만 진행하면 이 주장은 거짓이 된다.** RTX 5060 Ti 16GB에서 QLoRA 훈련이 실제로 돌아가는지 검증한 기록이 없다. OOM 없이 Gemma4-E2B(QLoRA VRAM ~12~14GB)가 16GB에서 돌아가는지는 핵심 실증 요건이다.
