# GPU 대여처 문의 체크리스트

Medical VQA VLM 석사 연구용 GPU를 다른 곳(개인/업체/랩 등)에서 대여할 때, 계약 전에 미리 확인해야
할 항목을 정리한 문서. 하드웨어 스펙만 맞다고 되는 게 아니라, 인프라 구조(스토리지·환경변수·접근
방식)를 모르고 시작하면 2026-07-22 RunPod pod에서 겪은 것과 같은 disk quota 장애를 그대로 반복할
수 있다 — 그날의 근본 원인은 스펙 부족이 아니라 "`$HOME`이 어디로 잡히는지", "캐시가 어느 디스크로
가는지"를 모른 채 시작한 것이었다. 상세 배경은 `docs/ENVIRONMENT_SETUP.md`, `docs/NEXT_SESSION.md` 참고.

---

## 1. 하드웨어

- [ ] GPU 모델이 무엇인가? (권장: RTX 4090 24GB, 최소: RTX 3090 24GB / A5000 24GB)
- [ ] VRAM 용량이 정확히 얼마인가?
- [ ] 멀티 GPU라면 몇 장이고, 각 장당 VRAM은 얼마인가? (16GB×2 조합도 가능은 함)
- [ ] 컨테이너/시스템 디스크 용량은? (권장 80GB 이상 — 모델 가중치 캐시용)
- [ ] 영구 저장 공간(볼륨) 용량은? (권장 100GB 이상 — 데이터셋 캐시 + 결과물)

## 2. 접근 방식

- [ ] SSH로 직접 접속 가능한가, 아니면 웹 터미널만 제공되는가?
- [ ] root 권한(또는 sudo)이 주어지는가? (환경변수를 자유롭게 export할 수 있어야 함)
- [ ] tmux/screen 같은 세션 유지 도구 사용이 가능한가? (며칠씩 걸리는 무인 학습을 detach 상태로 방치해야 함)
- [ ] 세션이 끊겨도(SSH 연결 종료 등) 실행 중인 프로세스가 죽지 않는가?

## 3. 스토리지 구조 (오늘 장애의 핵심 원인)

- [ ] "영구 디스크"라는 게 네트워크 볼륨(NFS/MooseFS 등)인가, 로컬 디스크인가?
- [ ] 인스턴스를 잠깐 멈춰도(Stop) 데이터가 보존되는가, 완전 삭제(Terminate)만 가능한가?
- [ ] 기본 홈 디렉토리(`$HOME`)가 어디로 잡히는가? — 이 값에 따라 캐시 저장 위치를 다시 설계해야 함
- [ ] 컨테이너 디스크와 영구 볼륨이 물리적으로 분리돼 있는가, 하나로 합쳐져 있는가?
- [ ] 디스크 용량 초과 시 정확히 어떤 에러가 나는가? (quota 방식인지 순수 용량 초과인지 — 진단 방식이 달라짐)

## 4. 네트워크 / 소프트웨어

- [ ] 외부 인터넷 접근이 열려 있는가? (PyPI, HuggingFace Hub, GitHub 접근 필요 — `uv sync`, 모델/데이터셋 다운로드에 필수)
- [ ] CUDA 드라이버 버전이 12.8 이상인가? (사전 설치된 템플릿/이미지 확인)
- [ ] Python 3.12 사용 가능한가, 아니면 직접 설치해야 하는가?
- [ ] Docker/커스텀 이미지를 올릴 수 있는가, 아니면 제공 템플릿만 써야 하는가?

## 5. 과금 / 운영 정책

- [ ] 시간당 정액 과금인가, 중단 가능(spot/interruptible)형인가?
- [ ] 중단 가능형이라면, 우선순위 높은 사용자가 나타나면 실행 중인 작업이 강제 종료되는가?
- [ ] 인스턴스를 꺼둔(Stop) 상태에서도 스토리지 비용이 청구되는가?
- [ ] 지출 한도(spending limit) 설정 기능이 있는가?
- [ ] 예상보다 오래 걸릴 경우(이번 프로젝트 기준 Phase 2만 ~55-85시간) 시간 단위 요금이 어떻게 되는가?

## 6. 참고 — 이번 프로젝트가 실제로 필요로 하는 것 (요약)

| 항목 | 값 |
|------|-----|
| 검증된 스택 | transformers 5.5.0 / torch 2.10.0+cu128 / trl 0.24 / peft 0.18.1 |
| 설치 방식 | `uv sync --extra unsloth` (반드시 `uv.lock` 그대로 재현) |
| Phase 2 예상 소요 | ~55-85시간 (RTX 3090 기준) |
| Phase 3 예상 소요 | ~200 GPU시간 (~8-9일) |
