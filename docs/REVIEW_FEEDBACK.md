# 🚨 석사학위 논문 설계서(v0.3) 비판적 검토 및 심사위원 예상 지적사항

본 문서의 검토 의견은 건국대학교 정보통신대학원 석사학위 논문 심사(디펜스) 과정에서 심사위원(교수진)으로부터 제기될 수 있는 **치명적인 방법론적 허점과 논리적 비약**을 신랄하게 짚어내고, 이를 방어하거나 수정하기 위한 지침을 제공합니다.

---

## 1. 15분 학습 시간 제한의 타당성 결여 (Phase 3)
*   **설계서 내용:** 각 HPO 전략(Optuna, Autoresearch 등)의 실험 1회당 순수 GPU 학습 시간을 **15분으로 고정**.
*   **비판적 지적:** 
    *   15분이라는 극단적인 조기 종료(Early Stopping) 제약은 하이퍼파라미터 최적화(HPO) 실험의 전제 조건을 파괴합니다.
    *   15분 내에 빠르게 수렴하는 조합(예: 높은 Learning Rate, 작은 Batch Size)이 임시로 높은 성능을 낼 수 있으나, 이는 **조기 수렴 또는 오버피팅의 결과**일 확률이 매우 높습니다.
    *   완전히 수렴(Convergence)하지 않은 '토막 학습' 결과로 에이전트의 우수성을 비교하는 것은 학술적 신뢰도가 떨어집니다. 이 조합이 전체 에포크(3 Epoch)를 완주했을 때도 최적일 것이라는 보장이 없습니다.
*   **🔥 예상 질문:** *"15분 학습하고 끈 모델의 성능이 온전히 학습을 끝낸 모델의 성능을 대변할 수 있다는 근거 래퍼런스가 있습니까?"*

## 2. Ablation Study 조건 선정의 샘플 편향 (Phase 2)
*   **설계서 내용:** 데이터 크기, LoRA Rank, Target Module 영향 분석 시 **"PathVQA 데이터셋 기준, 최적 모델 1개"**만 선택하여 실험.
*   **비판적 지적:** 
    *   선정한 3개 데이터셋(PathVQA, SLAKE, VQA-RAD)은 병리학, 방사선/CT, 일반 방사선으로 **도메인 이미지와 QA 특성이 완전히 다릅니다.**
    *   특정 1개 모델이 PathVQA에서 보인 경향성을 나머지 3개 모델과 2개 데이터셋에 그대로 대입하는 것은 심각한 **일반화의 오류**입니다.
    *   단 하나의 교차 조건으로 도출한 결론을 마치 "경량 VLM의 일반적 특성"인 것처럼 논문에 기술한다면 방법론적 게으름이라는 지적을 피할 수 없습니다.

## 3. 통계적 검증 설계와 현실적 타임라인의 정면 모순
*   **설계서 내용:** 4개 HPO 전략 간의 최종 성능 분포 비교를 위해 **각 전략을 5회 독립 반복**하여 Kruskal-Wallis test 수행.
*   **비판적 지적:** 
    *   **산술적 모순:** 전략 4개 × 전략당 40회 실험 × 5회 반복 = **총 800회의 실험**이 필요합니다.
    *   시간 예산이 15분이라 하더라도, 모델 로드, 대용량 데이터 셋 평가(Inference), LLM 에이전트 연산 및 Git Commit 타임아웃을 고려하면 1회당 최소 25~30분이 소요됩니다.
    *   즉, 800회 × 30분 = **약 400시간(순수 16.6일 동안 24시간 가동)**이 필요합니다. 설계서 표에 작성된 **"하룻밤 실험 수(~40회)"라는 표현과 정면으로 모순**되며, 보유한 RTX 5060 Ti 1대로는 물리적으로 불가능한 스케줄입니다.

## 4. Catastrophic Forgetting(치명적 망각) 측정의 실효성 부족
*   **설계서 내용:** 일반 능력 상실 측정을 위해 `VQAv2 validation subset (2,000 샘플)`을 대조군으로 사용.
*   **비판적 지적:** 
    *   실험 대상 모델들(Qwen, SmolVLM 등)은 이미 수억~수십억 개의 대규모 멀티모달 데이터로 사전학습(Pre-trained)된 거대 모델입니다. 겨우 2,000개의 무작위 샘플링 데이터셋으로는 지식 붕괴를 통계적으로 유의미하게 잡아내기 어렵습니다.
    *   본 연구의 의료 데이터셋 크기가 최대 4,998개이고 QLoRA(Rank 16) 수준의 가벼운 튜닝을 진행하는데, 이 정도 규모에서 발생하는 망각을 측정하는 것이 논문의 핵심 기여도(의료 성능 향상 및 HPO 자율화)와 무슨 상관관계가 있는지 당위성이 부족합니다.

## 5. 연구 질문(RQ3) 가설 검증 대상의 부적절성
*   **설계서 내용:** RQ3 귀무가설을 `H0: 자율 탐색 = Random Search`로 정의.
*   **비판적 지적:** 
    *   본 연구에서 Autoresearch 에이전트가 이겨야 할 진짜 대조군은 Random Search가 아니라, 이미 업계 표준으로 자리 잡은 베이지안 최적화 알고리즘 기반의 **Optuna (TPE)**입니다.
    *   만약 자율 에이전트가 Optuna보다 최종 Accuracy나 시간적 효율성 면에서 통계적으로 우월함을 증명하지 못한다면, 굳이 비싼 LLM API 비용을 지불해가며 에이전트 루프를 구축해야 할 당위성(Why?)이 사라집니다. 비교 기준점을 높여야 논문의 가치가 올라갑니다.

## 🛠️ 긴급 수정 및 디펜스 전략 권고 사항

1.  **Proxy Task(대리 과제) 레퍼런스 확보:** 15분 학습의 정당성을 부여하기 위해, 초반 학습 곡선(Learning Curve)의 경향성이 최종 수렴 성능과 높은 상관관계를 갖는다는 선행 연구 논문을 반드시 인용하고, 이를 'Proxy Task 기반 HPO'라고 학술적으로 포장하십시오.
2.  **실험 규모 현실화:** 단일 GPU 환경을 고려하여 HPO 반복 횟수를 5회에서 2~3회로 줄이거나, 대조군에서 Manual을 제외하고 Optuna 대 Autoresearch의 1:1 구도로 압축하여 총 실험 건수를 줄여야 타임라인을 맞출 수 있습니다.
3.  **Ablation Study 확장:** 적어도 '최적 모델 1개'를 쓰더라도 데이터셋은 3개 전체에 대해 Ablation을 수행하여 도메인별 특성 차이를 논문에 녹여내야 심사위원들을 설득할 수 있습니다.
