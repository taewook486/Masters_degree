### §4.4.4 "임상 가치 낮은 유형 편중" — 실측으로 확증했다

논문이 "향후 과제"로 남겼던 유형별 분해를 수행했다. `scripts/analyze_clinical_types.py` 신규.

**가능했던 이유**: Phase 1 제로샷은 PathVQA test 6,719건을 평가했고, **Phase 3의 810 trial은 전부 그 앞 500건을 평가**했다(810/810 질문 집합 일치를 전수 확인). 학습 seed는 달라도 평가셋은 고정이라 표본 대응 비교가 성립한다. 유형 분류는 `src/evaluate/clinical_significance.py:classify_clinical_type`을 그대로 재사용해 4.1.3과 동일 기준을 보장했다.

**결과 (v2 최고 trial 1030, 전체 개선 +0.1260)**

| 유형 | 가중치 | n | 제로샷 → 파인튜닝 | 상승분 점유 |
|---|---:|---:|---|---:|
| diagnosis | 1.0 | 3 | 0.0000 → 0.0000 | **0.0%** |
| location | 0.8 | 21 | 0.2381 → 0.7143 | 15.4% |
| measurement | 0.7 | 4 | 0.0000 → 0.0000 | 0.0% |
| description | 0.6 | 211 | 0.0190 → 0.1137 | 30.8% |
| temporal | 0.5 | **0** | — | — |
| yes_no | 0.5 | 244 | 0.6721 → 0.8156 | **53.8%** |
| unknown | 0.5 | 17 | 0.1765 → 0.0588 | −3.1% |

**편중은 실재한다** — 가중치 최하위 두 유형(yes_no, description)이 상승분의 **84.6%**를 차지하고, 이 둘이 표본의 91%다. 5개 조건 전부에서 yes_no가 상승분의 절반 이상(53.4~63.2%)이다.

**다만 단순화하면 틀리는 지점이 셋이다.** 논문에도 이 셋을 명시했다.

1. **최상위 가중치 유형은 판정 자체가 불가능하다.** 500건 중 diagnosis 3건, measurement 4건, temporal 0건. "개선 안 됐다"가 아니라 "판정할 표본이 아니다".
2. **개선폭 자체는 오히려 상위 가중치가 크다.** location(0.8)이 +0.4762로 전 유형 최대. 기여도 15.4%는 표본이 21건이라서다.
3. **WCA로 봐도 향상은 상쇄되지 않는다.** 0.1527 → 0.2627(+0.1099)로 전체 정확도 증가폭(+0.1260)과 대등하다.

**결론**: 편중의 원인은 유형별 학습 난이도가 아니라 **평가 표본의 유형 구성**이다. PathVQA test는 diagnosis가 6,719건 중 23건(0.34%)뿐이다. → 임상 중요 유형을 과표집한 평가셋 구축을 §5.4 향후 과제로 신설했다.

> Spearman 상관은 유효 유형이 4개뿐이고 동점이 있어 전 조건 +0.6325로 붙는다. 정보량이 없어 논문에는 넣지 않았다.

### 제출본 육안 확인 완료 — 조판 결함 3종 수정 (커밋 `9f10b9b`)

PDF를 실제로 렌더링해 확인했다. **내용 오류는 0건이고 조판 결함만 나왔다.**

1. **초록이 표 목차 페이지에 딸려 붙었다 (이번 변경이 만든 회귀).** 초록에 페이지 나누기가 아예 없었고, 8/16판은 표 목차가 마침 한 쪽에 맞아 우연히 정상으로 보였을 뿐이다. Table 4.4가 추가돼 목차가 한 줄 늘자 무너졌다.
2. **표가 페이지 경계에서 갈라졌다 — 국문 4건(Table 4.2·4.3f·4.4·4.4a) / 영문 2건(3.2·4.2b).** 넷은 8/16판부터 있던 기존 결함이다. Table 4.4는 캡션+헤더만 남고 데이터 8행이 다음 쪽으로 넘어가 있었다.
3. **두 줄짜리 캡션의 첫 줄만 페이지 끝에 남았다.** 1차 수정 후 오히려 나빠져 렌더링을 다시 보고 찾았다 — `keep_with_next`는 문단 **사이**만 묶고 문단 **내부** 분리는 못 막는다. `keep_together`를 함께 걸어야 한다.

수정: 캡션에 `keep_with_next` + `keep_together`, 표의 마지막 행을 뺀 전 행에 `keep_with_next`, 전 행에 `w:cantSplit`. 마지막 행까지 묶으면 아래 주석 문단을 끌어올려 여백이 과해지므로 제외했다.

검증: 표 분리 국문 4→0 / 영문 2→0(캡션 24개 전수 격자선 대조), 초록·장·참고문헌·부록 전부 새 페이지 시작, **목차 쪽번호 14항목 전수 실제 위치와 일치**, Table 4.4 양쪽 언어 렌더링 육안 확인.
